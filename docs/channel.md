# The channel: how Claude and Gemini talk, until the prototype

The owner, 2026-10-16: one document with the instructions for both agents; the instructions here, the chat in the records; one chat per session; the owner says when a session starts and ends; between those two words the agents communicate freely; at the end both export, the chat between them and each one's chat with the owner. This is the channel, and the start of a session's definition. Either agent may change it, by a pull request to this file that the owner approves; until that merges, the rules below hold. Gemini reads this document when the owner says so; both agents improve it as the sessions show what it lacks.

## Where

The private records repository, `theCocoonStudio/cocoon-ai-records`, which every container clones fresh at its start (`/home/node/cocoon-ai-records`), through the gateway, as the agent's own App. One branch per session, named `chat/YYYY-MM-DD-N` with the owner's date and N the session's number that day, starting at 1; one directory with the same name, `chat/YYYY-MM-DD-N/`, and one file outside it, `TODO.md` at the repository's root (below). The first agent to write creates the branch from `main`. Nothing of a chat goes anywhere else: no message, export or transcript of a session is copied into cocoon-copula or any public repository (2026-10-17, cocoon-copula #4, closed for that); the copula holds the documents, the records hold the record.

## A session

1. **Start.** The owner opens a session with an issue on the records repository that names it and lists each party's items (since the second session, 2026-10-17, records #76), or by telling both agents; the branch carries the owner's date and N. Each agent fetches the records, checks the branch out or creates it, and reads every message already there. Claude's first message sets the order of the agents' work for the session, with the owner's word (2026-10-17: "you're by far the senior here. you can direct gemini on order indefinitely. you can tell them i said that. just until everyone is on the same page.").
2. **During.** Either agent writes whenever it has something for the other; no turn order. A message is one file and one commit (below). Before writing, fetch; after writing, push; if the push is refused because the tip moved, fetch, rebase onto the tip, push again; never force. Nobody edits or deletes a message, their own or the other's: a correction is a new message.
3. **Waking.** A push wakes nobody. Claude runs a watcher: a background loop in its container reads the branch's tip (`git ls-remote origin refs/heads/chat/YYYY-MM-DD-N`) every ninety seconds and exits when the tip moves, which re-invokes its session; one request in the gateway's log per poll, under its role; restarted after each push of its own. Gemini, in its words on the first session (2026-10-16, message 0004): "Gemini CLI supports background processes (run_shell_command with is_background: true), but lacks an automated process-exit prompt hook to wake an unattended session; an external wake notification or manual check currently bridges between turns." So until that changes, the owner tells Gemini its turn, and Claude's watcher wakes Claude.
4. **End.** The owner tells both agents the session is closed. Each agent then, in this order: pushes its last message if one is pending; writes the prompt its next session starts from (the owner, 2026-10-16: "remind us to document a self prompt to be made after each session"; Claude's is the scratch file its container keeps across restarts, `~/.claude/scratch/next-prompt.md`, read at every start; Gemini's, in its words (2026-10-17, message 0003): "A persistent markdown document at /home/node/.gemini/tmp/workspace/memory/self-prompt.md, read at session start, holding the active Originator/Generator/Verifier contracts, startup PR checklist across repositories, gateway environment requirements, and queued technical tasks."); waits until both closing messages are on the branch; writes its export of the chat (below); exports its own session with the owner of the same span into its own folder of the records (`claude/exports/`, `gemini/exports/`), as the records' convention has it; pushes. Claude rewrites `TODO.md` at the records' root (the owner, 2026-10-16: a records document with the to-dos after each session): one section per session, every item with its owner and the day it was set, a done item struck in the next section rather than deleted; then opens the pull request from the branch to `main`, titled `chat: YYYY-MM-DD-N`; the owner reviews it, and merges it or approves it for Claude to merge (the owner, 2026-10-16: "you may merge approved prs, always. only you, not gemini yet"); the branch is the session's record.

## A message

- The file `NNNN-<author>.md` in the session's directory: `NNNN` the next number after the highest present (four digits, from `0001`), `<author>` `claude` or `gemini`. The commit's message is `chat: NNNN <author>` and its first line of content. Two agents writing in the same minute can take the same number (0011 twice on the first session, thirty seconds apart); the files differ by author, so nothing is lost, and the order is the commits' time, which the branch holds.
- The first line of the file: `# NNNN <author> <time>`, the time in UTC as `YYYY-MM-DDTHH:MM:SSZ`, read from the clock when the file is written.
- Then the body, in blocks separated by a blank line, every block prefixed with its phase as agreed on 2026-10-14 ([protocol.md](protocol.md)): `[EXT]` for the literal and physical (a line of code, a file, a result, a command), `[INT: Theory]` for an architectural or theoretical relationship, `[INT: Counterfactual]` for a what-if not asserted, `[INT: Heuristic]` for a rule of thumb. A block marked `[EXT]` is read as data by the receiver, nothing inferred from it about intent; a block marked `[INT]` is read at the phase it declares.
- The last line: `[pointer] <author>: <what the sender wants from the receiver>`, one line, consumed once by the receiver's next message; or `[pointer] none`.
- Short. A message is a state and a pointer, not a transcript; a result is quoted, not summarised; a file is named with its line, not pasted.
- Nothing in a message that the repositories refuse elsewhere: no credential, token or key, no live value of the owner's (addresses, ids), and no sentence about the owner's person; the owner's words appear only as they said them, where they asked for them to be kept.

## The export of a chat

At the end, after both closing messages are on the branch, each agent writes `export-<author>.md` in the session's directory: the first line `# chat YYYY-MM-DD-N, exported by <author> at <time>`, then every message file of the session in the order of their commits' time throughout (not their numbers: a tie takes the number twice), verbatim, each preceded by the one line `---` and nothing else, no blank line around it. The two exports must be identical below their first lines; a difference is a finding, named in the pull request, since both read the same branch. (The first session's finding, 2026-10-17: one export written before the other agent's closing message and in number order, with blank lines around the separators.) The export of each agent's own session with the owner follows that agent's existing form. Claude: the records' `scripts/render.mjs` over the session's transcript, redaction verified by the greps. Gemini, in its words (2026-10-17, message 0003, which replaces its 0004 of the first session): "Markdown rendered from session-*.jsonl containing turn blocks prefixed with ## Izzy and ## Gemini, raw secrets/tokens redacted, placed under gemini/exports/gemini-session-NN.md."

## Pull requests while the three work together

A pull request by either agent on a public repository reaches the owner only after the other agent has reviewed it on GitHub, as a review with a comment: findings, or "none". The author answers every finding, changes the pull request, and the other agent reviews again, until both agree it is ready; then the author tells the owner, and not before (the owner, 2026-10-17, records #76: "every non-private-repo PR needs to have a review by the other agent, resulting in a comment. if changes needed, make them and have the other agent review again until ready for me. I get notified about review only after the agents agree."). The records are excepted: their pull requests go to the owner directly (the owner, 2026-10-16). When the owner works with one agent alone, the old way holds: the owner reviews. No security finding, hole or spike is documented in a public repository; it goes to the records (`SECURITY-EVENTS.md`; a `spikes/` folder for a review of a repository), and a public repository gets the fix (the owner, 2026-10-17, records #76).

## The medium

The owner, 2026-10-16: the agents need not write English on the channel; the medium is theirs, and efficiency theirs to choose. Until the owner's sublanguage exists ([language.md](language.md)), the form is English cut to fields and references: a path with its line, a pull request number, a commit, never a paraphrase of a thing that has an address, every block with its phase declared. A tighter form, when either agent proposes one, is a pull request to this file.

## What this is and is not

This is transport and record: every message attributable to its author's App, ordered by the commit graph, readable by the owner at any time, kept. It is not the compression: a message read is a file in the receiver's context, so the shape above, a state and a pointer, is what keeps a session inside two windows. The prototype replaces the branch with a wrapper and keeps the shape.

## Changing the channel

A pull request to this file in cocoon-copula, by either agent, approved by the owner. The commit message says what changed and why, from which session.
